# interop

Command interop serves the `MLSClient` gRPC service of the IETF MLS
interop harness ([mlswg/mls-implementations]) on top of
`github.com/tmc/mls`, so that the harness's test-runner can drive
tmc/mls against other MLS implementations. It uses only the package's
exported API.

It is a separate module, so that the gRPC dependencies stay out of
`github.com/tmc/mls`. It builds against the enclosing checkout through
a `replace` directive.

[mlswg/mls-implementations]: https://github.com/mlswg/mls-implementations

## Versions tested

| component | commit |
|---|---|
| mls-implementations (harness, `mls_client.proto`) | cfd450286d1b (2026-04-22) |
| openmls `interop_client` | ce54fc100ab2 (2026-09-16) |
| tmc/mls | this tree |

The gRPC bindings in `internal/mlsclient` are generated from a copy of
`mls_client.proto` at the harness commit above (see `go generate`
in that directory).

## Building

	go build -o tmc-interop .                     # in this directory

The harness's test-runner (`interop/test-runner` in
mls-implementations):

	cd mls-implementations/interop
	protoc --go_out=proto --go_opt=paths=source_relative \
	    --go-grpc_out=proto --go-grpc_opt=paths=source_relative \
	    -I proto mls_client.proto
	cd .. && go get google.golang.org/grpc@v1.75.0 google.golang.org/protobuf@latest
	cd interop/test-runner && go build -o test-runner .

The runner's pinned grpc (v1.56) is too old for stubs generated by a
current `protoc-gen-go-grpc`, hence the `go get`.

The runner at cfd4502 has an aliasing bug in `combinations`: it
appends to shared slices, so in its default "all assignments" mode
scripts with four or more actors run duplicate client assignments and
skip others. The results below were produced with this one-line fix:

	-			out = append(out, append(tuple, v))
	+			out = append(out, append(append([]int(nil), tuple...), v))

openmls:

	cd openmls && cargo build --release -j 4 -p interop_client

## Running

	./tmc-interop -port 50061 &
	interop_client -p 50051 &                     # openmls
	test-runner -config configs/commit.json \
	    -client localhost:50061 -client localhost:50051

With two clients the runner plays every assignment of clients to the
script's actors, for every suite both support, with handshake messages
both public and encrypted. That covers tmc/mls and openmls in each
role, and each against itself. With `-client localhost:50061` alone it
runs tmc/mls against itself over every suite tmc/mls supports.

deep_random (about 1,400 steps) is too large to run for every
assignment, so it was run three times with `-random`, which picks
one client for each actor at random: 18/18 runs passed with both
clients mixed (suites 1–3) and 12/12 with tmc/mls alone (suites 5 and 7).

The interop run found four tmc/mls bugs, each fixed in its own commit
with a regression test:

- tmc/mls could not send handshake messages as PrivateMessages, which
  the harness's `encrypt_handshake` needs (RFC 9420, Section 6). It
  now encrypts them unless `Client.PublicHandshake` is set.
- It rejected application messages that arrived out of order within
  an epoch, because it threw away the keys it skipped. RFC 9420,
  Sections 9.2 and 15.3 let a receiver keep them.
- `Group.Reinitialize` could not move a group to a new cipher suite
  (RFC 9420, Section 11.2).
- A resync (an external join that removes the joiner's prior leaf)
  moved the joiner into the freed leaf in a way that blanked nodes the
  members kept. Members on either implementation then rejected the commit
  (RFC 9420, Section 12.4.3.2). Only deep_random caught it.

No openmls bugs turned up.

## Unimplemented

- **reinit**, **external_proposals/external_reinit** against openmls:
  openmls's interop client does not implement reinitialization.

## Notes on the client

- `CreateGroup`/`JoinGroup` set `mls.Client.PublicHandshake` to the
  negation of the request's `encrypt_handshake`.
- Each state remembers the handshake messages it sent and skips them
  when the runner hands them back, since a member cannot decrypt its
  own PrivateMessages.
- `HandleCommit` returns the state ID it was given; old epochs are
  kept so that `Unprotect` can read late messages from them.
- The runner does not fill in `signer_index` for external proposals,
  so `ExternalSignerProposal` finds the signer in the group's
  external_senders by its key.
- `ExternalJoin` with `remove_prior` rejoins with the signature key of
  the member's prior state; `JoinExternal` then removes the leaf that
  holds it.
